# 飞书群任务来源

在飞书群里 @ Aster 绑定的应用机器人并写下需求。飞书提供的群、发送者和 @ 记录通过授权与规则检查后，Aster 使用共用的任务判断模型。模型返回 `process` 后创建工单，由一个默认 Worker 在绑定的工作区内执行。

```text
飞书群 @ 应用机器人 → 群和人员授权 → 关键词规则 → DeepSeek
                                                ├─ process → 工单 → Worker
                                                └─ ignore → 记录原因
```

## 首次启用

1. 在飞书开放平台为当前应用开通接收群聊 @ 机器人的权限 `im:message.group_at_msg:readonly`。在**事件与回调 → 事件配置**选择长连接，添加**接收消息**事件 `im.message.receive_v1`，按飞书流程发布应用版本。长连接由 Aster 的飞书任务来源启动，页面会显示连接状态。[飞书长连接指南](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)
2. 将应用机器人加入目标群。打开 Aster 要执行工作的项目和对话，在左侧**飞书**页添加群来源。用**读取机器人所在群聊**选择目标群。可通过**添加当前用户**填写当前授权用户的 Open ID，也可填写其他允许提需求的人员。
3. 按需填写关键词。填写时，正文命中任意一项才会交给模型。保存后手动启用来源，在群里 @ 机器人并描述任务。

飞书页展示来源连接状态、入站事件、判断回执和关联工单。工单页可以查看 Worker 进度、回答待办和停止任务。判断模型默认使用 `deepseek-flash`，与 GitHub 共用已有的独立判断设置。[任务判断模型](task-triage.md)

若飞书控制台提示先建立长连接，先完成群来源配置并启用接收，再回到飞书控制台保存长连接与事件配置。

## 授权和恢复

- 每个来源绑定已验证的应用机器人、群和对话。授权匹配使用飞书事件中的真实标识。群内普通文字、机器人发言、单聊和应用机器人未被 @ 的消息不进入模型。
- 接收只处理启用后的新消息。飞书重投同一消息时使用原回执。判断关闭、失败或中断时，页面展示原因供操作者检查。启用后可用新的 @ 消息重新提出需求。
- Worker 沿用绑定对话的工作区、Agent、Skill、模型和审批规则。暂停来源或更改授权会使旧的派发授权失效。已经产生的外部操作按工单的执行记录核验。
- 应用凭据留在官方 CLI 已配置的本机目录及凭据存储中。飞书来源表记录群与应用身份的绑定，任务文本保存在本机 Runtime。官方 CLI 自己的长连接诊断保留在其配置目录下的 `events` 中。管理页的**读取机器人所在群聊**是一次显式的飞书只读操作。
