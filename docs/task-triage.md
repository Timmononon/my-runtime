# 独立任务判断模型（0.1.10）

新 GitHub 事件和飞书群请求先通过各自的来源、账号和规则检查，再由独立模型判断
是否需要开展工作。默认提供商为内置 `deepseek`，模型为 `deepseek-flash`，
推理强度为 `none`。此选择独立于来源聊天与 Worker 的模型，不需要另外部署服务。
提供商密钥复用现有模型提供商管理，仍只保存在独立凭证文件。

## 判断和执行

```text
GitHub / 飞书群 → 来源和规则检查 → 按来源选择提示词 → process → 创建默认 Worker
                                             └→ ignore（记录原因）
```

模型只有 `process`（处理）和 `ignore`（忽略）两个业务结果，返回
`{"decision":"process|ignore","reason":"原因"}`。GitHub 提示词关注代码评审、缺陷、功能需求和 CI 等仓库工作，
也接纳“查看有没有 bug”这类范围较宽的请求。飞书提示词接纳群里的日常问答、翻译、总结、内容整理和提纲撰写。
单纯寒暄、致谢和没有新要求的状态通知会被忽略。缺少细节时由 Worker 排查和补问。
判断模型看到来源事件和可信配置中的处理范围，外部正文始终作为不可信数据。结果必须通过严格 JSON 校验。

来源授权仍由代码决定，判断模型不能放宽账号、工具、目录或发布权限。只有
通过校验且身份仍有效的 `process` 回执才允许创建任务。模型超时、输出不完整、
格式错误、配置或凭据不可用，以及判断开关关闭，都保留为失败记录，
业务 `decision` 为 `null`，不会自动跳过判断去执行。超出输入预算时记录错误，不截取可能遗漏
更正或否定语义的部分正文再自动开工。

能力 `task_triage_binary_v1` 表明这套二选一约定。旧版已完成的 `needs_info`
回执原样保留，界面标为旧版判断；不篡改历史，也不因升级而自动重新执行旧 Issue。

已有工单的获准跟进继续进入同一个任务；独立 `/aster stop` 指令直接执行原有
停止控制，不依赖判断模型。此轮只补齐新任务的判断层，GitHub 自动任务仍默认
一个 Worker；模型 Router 自动拆分多个 Worker 不在这一轮实现中。

## 独立配置

工作台的 GitHub 和飞书页面共用判断模型设置，各自显示来源事件与判断结果。配置保存在当前 Runtime 的
独立 SQLite 设置记录，带有修订号，不跟随聊天模型切换，也不能由 Issue 正文修改。
先在现有“模型提供商”设置中配置凭据，再选择对应的提供商、模型与推理强度。
默认 DeepSeek 无需另一份密钥。

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| `enabled` | `true` | 启用判断；关闭时暂停新事件自动创建任务 |
| `provider_id` | `deepseek` | 独立提供商配置引用 |
| `model` | `deepseek-flash` | 独立模型 |
| `reasoning_effort` | `none` | 推理强度 |
| `processing_scope` | 空文本 | 操作者配置的处理范围和判断补充要求 |
| `timeout_seconds` | `30` | 单次判断时间预算 |
| `max_input_chars` | `16000` | 判断输入上限 |
| `max_output_tokens` | `768` | 单次输出预算 |
| `max_calls_per_poll` | `4` | 单次 GitHub 路由允许的新判断次数 |
| `max_requests_per_hour` | `60` | 当前 Runtime 每小时判断请求预算 |

普通候选仍先受现有任务策略 `off/observe/auto` 与关键词规则约束。
关闭、只观察或不匹配的普通候选不请求模型。明确获准的 GitHub 人工指令不要求关键词匹配。飞书群来源按自身人员名单、真实 @ 和
可选关键词筛选。两者都必须通过独立模型判断。来源关闭、只读、历史基线、重复事件
和未授权账号不会触发新判断。查看和保存设置不会发送试验请求。

## 回执与接口

- `GET /tasks/triage/settings`：读取独立配置及修订号。
- `PATCH /tasks/triage/settings`：携带 `expected_revision` 保存配置。
- `GET /tasks/triage/decisions`：读取持久化判断，可按 `source_session_id` 筛选。

所有接口使用现有本机 API 鉴权。读取接口保持离线。判断记录保存事件关联、
配置版本、提供商／模型、结果、原因、补充问题、用量和安全错误类别。用量
缺失保持未知。模型请求之前先保存意图，同一事件重投复用回执；中断或失败
不会自动重放。判断期间来源、规则、提供商凭据或设置变化会阻止旧结果建任务。

DeepSeek 接口依据其[官方 Responses API 文档](https://api-docs.deepseek.com/guides/responses_api/)，
沿用 Aster 现有适配器。
